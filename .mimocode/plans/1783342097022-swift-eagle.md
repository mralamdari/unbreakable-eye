# Unbreakable Eye — Senior DevOps Engineering Review

---

## 1. What Does This System Do?

**Unbreakable Eye** is a **production-grade edge AI inference microservice** for real-time computer vision in retail/surveillance environments. It provides:

- **Person Detection**: Detects people in video streams using multiple YOLO-family models (YOLOv8, YOLOX, RT-DETR, D-FINE, OpenVINO)
- **Person Re-Identification (Re-ID)**: Uses OSNet embeddings to match the same person across frames/cameras via pgvector cosine similarity
- **Multi-Camera Support**: Shared batched YOLO inference across multiple RTSP camera streams
- **Real-Time Streaming**: MJPEG streaming with annotated bounding boxes via FastAPI
- **Analytics Dashboard**: Web UI showing detected customers, dwell times, loitering alerts, and visitor analytics
- **Per-User Camera Management**: Each user registers cameras, the system auto-starts pipelines on login

**Architecture Flow:**
```
RTSP Camera → Reader Process → Shared Memory Ring Buffer → Batched Detector → Embedder/Re-ID → Annotated Output → FastAPI MJPEG Stream → Browser Dashboard
```

The system uses a sophisticated multi-process architecture with shared memory ring buffers, ByteTrack for object tracking, and PostgreSQL + pgvector for persistent embedding storage with HNSW indexing.

## 2. PROS (What's Done Well)

### 2.1 Architecture & Design
- **Clean Factory Pattern**: `src/vision/factory.py` + `BaseDetector` abstraction allows hot-swapping inference engines (YOLO, ONNX, OpenVINO, HF Transformer) with zero code changes
- **Multi-Process Architecture**: Reader → Batched Detector → Embedder pipeline correctly separates concerns across OS processes with proper dependency ordering
- **Shared Memory Ring Buffers**: Slot-based SHM design avoids memory copies between processes — high-performance IPC
- **Three-Phase Pipeline Restart**: `_disconnect_streams()` → `_teardown_sync()` → `_startup_sync()` ensures clean lifecycle management without blocking the event loop
- **12-Factor App Configuration**: Pydantic Settings with `.env` loading, strict typing via Enums

### 2.2 Model Flexibility
- **6 Model Architectures**: YOLOX, D-FINE, RF-DETR, OpenVINO, Ultralytics, YOLO ONNX — all through one factory
- **Automatic Model Downloading**: `model_resolver.py` handles HuggingFace Hub, Ultralytics export, GitHub releases, and Intel Open Model Zoo
- **Hardware Detection Script**: `scripts/detect_hardware.py` auto-detects NVIDIA/Apple Silicon/Intel GPU
- **GPU Overlay Compose**: `docker-compose.gpu.yml` for NVIDIA CUDA with nvidia-container-toolkit

### 2.3 DevOps & Infrastructure
- **Docker Native**: Multi-stage Dockerfile (production ~500MB), separate GPU Dockerfile, dev Dockerfile with hot-reload
- **Nginx Reverse Proxy**: Static file serving offloaded from FastAPI, proper MJPEG buffering disabled
- **PostgreSQL + pgvector**: HNSW-indexed vector search for real-time Re-ID matching
- **CI Pipeline**: GitHub Actions with Ruff linting + MyPy type checking
- **Structured Logging**: Loguru with JSON mode for production (Datadog/ELK ready)

### 2.4 Security & Production Readiness
- **Non-Root Container User**: `appuser` in production Dockerfile
- **Session-Based Auth**: itsdangerous signed cookies, bcrypt password hashing
- **Connection Pooling**: ThreadedConnectionPool with configurable min/max
- **Graceful Shutdown**: Proper process termination order (detector → embedders → db_writer)

### 4.2 Edge Device Deployment Strategy

#### For NVIDIA Jetson (Jetson Nano, Xavier, Orin):
```yaml

  fastapi:
    build:
      context: .
      dockerfile: infra/docker/Dockerfile.jetson
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]

      - DEVICE=cuda
      - WORKING_WIDTH=320    # Reduced for Jetson
      - WORKING_HEIGHT=320
```

**Jetson Dockerfile:**


### 4.4 Recommended Changes for Edge

1. **Make Pipeline Active**: Uncomment `src/engine/pipeline.py` or create a lightweight edge version
2. **Add Hardware Auto-Detection**: Integrate `detect_hardware.py` into Dockerfile build
3. **Add Resource Limits**:
   ```yaml
   deploy:
     resources:
       limits:
         cpus: "4.0"
         memory: 4G
   ```
4. **Add Health Check Endpoint**:
   ```python
   @app.get("/health")
   async def health():
       return {"status": "ok", "cameras": len(processors)}
   ```
5. **Add Graceful Degradation**: If GPU not available, fall back to CPU with reduced resolution
6. **Add MQTT/WebSocket for Cloud Sync**: Send embeddings to cloud instead of requiring local PostgreSQL on edge
7. **Add Model Warmup**: Pre-load models at startup to avoid first-request latency
8. **Add Prometheus Metrics**: `/metrics` endpoint for monitoring
