# Retail Analytics Expansion Plan

## Goal
Transform the existing people detection/tracking system into a full retail analytics platform that gives shop owners actionable business data. Must work on CPU-only hardware, scale with GPU.

## User Choices
- **Privacy**: Faces only (GDPR blur)
- **Zones**: Interactive drawing on dashboard
- **Heatmaps**: Configurable time window
- **Data**: Raw detections retained 7 days, aggregated data retained 30 days, auto-purge

---

## Phase 1: Database Schema + Config Foundation

### 1a. New tables in `src/core/database.py`

```sql
-- Zone definitions per camera
CREATE TABLE IF NOT EXISTS zones (
    id          BIGSERIAL PRIMARY KEY,
    camera_id   BIGINT NOT NULL REFERENCES cameras(id) ON DELETE CASCADE,
    name        TEXT NOT NULL,
    polygon     JSONB NOT NULL,          -- [[x1,y1],[x2,y2],...] in normalized coords (0-1)
    zone_type   TEXT DEFAULT 'area',     -- 'area' | 'line' (line = entry/exit counter)
    color       TEXT DEFAULT '#4f8cff',
    created_at  DOUBLE PRECISION NOT NULL
);

-- Zone entry/exit events
CREATE TABLE IF NOT EXISTS zone_events (
    id          BIGSERIAL PRIMARY KEY,
    zone_id     BIGINT NOT NULL REFERENCES zones(id) ON DELETE CASCADE,
    camera_id   BIGINT NOT NULL REFERENCES cameras(id),
    customer_id BIGINT REFERENCES customers(id),
    tracker_id  INTEGER,
    event_type  TEXT NOT NULL,           -- 'enter' | 'exit'
    timestamp   DOUBLE PRECISION NOT NULL,
    dwell_seconds REAL DEFAULT 0
);

-- Aggregated analytics (hourly snapshots per camera)
CREATE TABLE IF NOT EXISTS analytics_hourly (
    id              BIGSERIAL PRIMARY KEY,
    camera_id       BIGINT NOT NULL REFERENCES cameras(id),
    hour_bucket     DOUBLE PRECISION NOT NULL,  -- start of hour (unix)
    unique_visitors INTEGER DEFAULT 0,
    total_detections INTEGER DEFAULT 0,
    avg_dwell_secs  REAL DEFAULT 0,
    peak_occupancy  INTEGER DEFAULT 0,
    new_visitors    INTEGER DEFAULT 0,
    return_visitors INTEGER DEFAULT 0
);

-- Raw detection events (retained for 7 days)
CREATE TABLE IF NOT EXISTS detection_events (
    id          BIGSERIAL PRIMARY KEY,
    camera_id   BIGINT NOT NULL REFERENCES cameras(id),
    tracker_id  INTEGER,
    customer_id BIGINT REFERENCES customers(id),
    timestamp   DOUBLE PRECISION NOT NULL,
    bbox_x1     REAL, bbox_y1 REAL, bbox_x2 REAL, bbox_y2 REAL,
    confidence  REAL,
    center_x    REAL, center_y REAL,
    zone_id     BIGINT REFERENCES zones(id),
    velocity_x  REAL DEFAULT 0,
    velocity_y  REAL DEFAULT 0
);
```

## Phase 4: Heatmap Accumulation

### 4a. Heatmap accumulator — new file `src/engine/heatmap.py`

```python
class HeatmapAccumulator:
    """Rolling heatmap that accumulates person center positions over time."""
    - heatmap: np.ndarray (display_height, display_width) float32, decays over time
    - add_position(center_x, center_y, timestamp)
    - decay(elapsed_time) — exponential decay toward zero
    - get_heatmap() -> np.ndarray (normalized 0-255 for visualization)
    - persist_to_db() — snapshot to analytics_hourly
    - Configurable retention window via HEATMAP_RETENTION_SECONDS
```

**Approach**: Instead of using `sv.HeatMapAnnotator` (which only shows current-frame positions), maintain a custom accumulator that:
1. Increments a Gaussian at each person's center position every frame
2. Applies exponential decay so old positions fade
3. Normalizes and renders as a color-mapped overlay

This gives a smooth, real-time heatmap that shows traffic patterns over the configurable time window.

### 4b. Integration in `embedder_worker`

Each camera's embedder_worker gets a `HeatmapAccumulator` instance. After tracking:
```python
for det in detections:
    cx, cy = center_point
    heatmap_accumulator.add_position(cx * scale_x, cy * scale_y, time.time())
annotated = heatmap_accumulator.render_overlay(annotated)
```

Returns the current heatmap as a JSON grid or PNG image.

## Phase 5: Analytics Data Collection + Persistence

### 5a. Event logging in `src/engine/pipeline.py`

In `process_frame`, after zone analytics, log structured events to a new `analytics_queue`:

```python
# Per detection per frame:
analytics_queue.put(("detection", {
    "camera_id": cam_id, "tracker_id": tid, "customer_id": track_to_customer.get(tid),
    "timestamp": now, "bbox": [x1,y1,x2,y2], "confidence": conf,
    "center": [cx, cy], "zone_id": current_zone_id,
    "velocity_x": dx/dt, "velocity_y": dy/dt
}))

# Per zone entry/exit:
analytics_queue.put(("zone_event", {
    "zone_id": zone_id, "camera_id": cam_id, "tracker_id": tid,
    "customer_id": customer_id, "event_type": "enter"|"exit",
    "timestamp": now, "dwell_seconds": elapsed
}))
```

### 5b. Analytics writer — new file `src/core/analytics_writer.py`

Separate process (like db_writer) that:
1. Batches events from analytics_queue
2. Writes detection_events in bulk (INSERT ... VALUES ... , ... , ...)
3. Aggregates into analytics_hourly every hour (cron-like via timer)
4. Runs retention cleanup:
   - DELETE FROM detection_events WHERE timestamp < now() - 7 days
   - DELETE FROM analytics_hourly WHERE hour_bucket < now() - 30 days
5. Writes zone_events immediately (low volume)

### 5c. Hourly aggregation job

```python
def aggregate_hourly(cam_id, hour_start):
    """Roll up detection_events into one analytics_hourly row."""
    - COUNT(DISTINCT customer_id) → unique_visitors
    - COUNT(*) → total_detections
    - AVG(dwell_seconds from zone_events) → avg_dwell_secs
    - MAX simultaneous tracker_ids → peak_occupancy
    - COUNT(DISTINCT customer_id WHERE customer.total_visits=1) → new_visitors
    - COUNT(DISTINCT customer_id WHERE customer.total_visits>1) → return_visitors
```

## Key Architecture Decisions

1. **Analytics writer is a separate process** — like db_writer, it owns all analytics DB writes. The pipeline never blocks on DB.

2. **Heatmap is in-memory with decay** — not a DB query. The accumulator runs in the embedder_worker process. The API endpoint reads from the accumulator directly (via shared memory or a queue).

3. **Zone coordinates are normalized (0-1)** — stored as JSONB. Scaled to inference resolution at runtime. This makes zones resolution-independent.

4. **Raw detections retained 7 days, aggregated 30 days** — analytics_hourly provides fast queries for dashboards; detection_events available for forensic analysis.

5. **All features are toggleable** — PRIVACY_BLUR, HEAT_ENABLED, zone drawing, etc. can be turned on/off per deployment without code changes.

6. **Face-only blur** — uses BlurAnnotator on person detections. For better face-specific blur, Phase 8 can add a face detector.
