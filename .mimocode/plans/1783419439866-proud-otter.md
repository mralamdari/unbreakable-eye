# Fix: Slow Docker rebuilds during development

## Problem
Running `docker compose -f docker-compose.dev.yml up --build` reinstalls all pip packages every time, even when only `src/` files changed. This is unnecessary because the dev setup uses volume mounts for live code editing.

## Root Cause
The user runs `--build` for every code change. The `--build` flag forces Docker to re-evaluate the Dockerfile. When the layer cache is invalidated (e.g., `.dockerignore` changes, context timestamp changes), Docker rebuilds the `pip install` layer — which downloads and installs ~37 packages from PyPI.

## Solution: Stop using `--build` for src/ changes

The dev setup is already optimized:
- `docker-compose.dev.yml` line 29: `./src:/app/src` — volume mount for live code
- `Dockerfile.dev` line 23: uvicorn runs with `--reload` — auto-detects file changes
- `Dockerfile.dev` line 20: `src/` is NOT copied into the image — it's always served from the volume

### Correct workflow
```bash
# First time: build + start
docker compose -f docker-compose.dev.yml up --build

# After that: just start (no --build)
docker compose -f docker-compose.dev.yml up

# Edit src/ files → uvicorn reloads automatically → instant feedback

# ONLY rebuild when requirements.txt changes
docker compose -f docker-compose.dev.yml up --build
```

### No code changes needed
The Dockerfile and docker-compose are already correctly configured. The fix is purely a workflow change — don't pass `--build` unless dependencies actually changed.
