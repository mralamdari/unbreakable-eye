# Fix: Container crashing with exit code 135 (SIGBUS)

## Root Cause

Exit code 135 = 128 + 7 = **SIGBUS** (bus error). This happens when a process accesses shared memory that has been unlinked/closed.

The crash sequence:
1. User navigates to `/monitor` → `_background_resume()` starts pipelines
2. Pipelines run successfully for a few seconds (detections flow)
3. Something triggers `apply_changes` again (e.g., the background resume completes, or a second request triggers it)
4. `_teardown_sync` calls `proc.stop()` on each pipeline
5. `proc.stop()` calls `proc.join(timeout=2)`, then `proc.terminate()`, then `proc.join(timeout=1)`
6. If the embedder process doesn't terminate in time, `_cleanup_shm()` unlinks shared memory while the embedder is still reading from it → **SIGBUS**

The `_cleanup_shm()` is called unconditionally after the join/terminate loop, even if the process is still alive.

## Plan

### Fix 1: Make `_cleanup_shm()` safe — only unlink after process is dead
**File**: `src/engine/pipeline.py` — `VisionPipeline.stop()` method (~line 317)

After the terminate + join loop, check if the process is actually dead before unlinking shared memory. If not, force-kill with SIGKILL and wait.

```python
def stop(self):
    self.stop_event.set()
    try:
        self.det_queue.put_nowait(None)
    except Exception:
        pass
    for proc in (getattr(self, "p_reader", None),
                 getattr(self, "p_embedder", None)):
        if proc is not None and proc.is_alive():
            proc.join(timeout=3)
            if proc.is_alive():
                proc.terminate()
                proc.join(timeout=3)
            if proc.is_alive():
                proc.kill()          # SIGKILL — last resort
                proc.join(timeout=2)
    self._cleanup_shm()
```

This ensures processes are dead before shared memory is unlinked.

### Fix 2: Restore `--reload` for dev workflow (optional, low risk)
**File**: `infra/docker/Dockerfile.dev`

The `--reload` flag was NOT the cause of the event loop freeze — the original code worked with it. The freeze was caused by the blocking middleware. Since the middleware is now non-blocking, `--reload` should be safe to restore. However, this is optional and low-risk to leave out.
