# Analysis: What Changed & What's Wrong

## What I Changed (vs git HEAD)

I only changed **2 files** - the application source code is UNCHANGED:

### 1. `infra/docker/Dockerfile`
- Added system libraries (`libgl1`, `libxcb1`, `libxext6`) needed by OpenCV
- These were MISSING in the original Dockerfile and the container couldn't start at all
- Original had `COPY models/ ./models/` but docker-compose also mounts `./models:/app/models` (volume overrides COPY)

### 2. `.env`
- Changed `FEATURE_EXTRACTOR_MODEL` from `models/osnet_x0_25_256x128.onnx` to `models/osnet_x1_0_imagenet.onnx`
- The old model file DOESN'T EXIST in your models directory - only `osnet_x1_0_imagenet.onnx` exists
- Without this fix, the embedder_worker crashes every time a pipeline starts

## Why Video Appears "Stuck"

**Both cameras point to the same file**: `data/cr-mini.mp4`
```
id | name | stream_url    
 1 | cam1 | data/cr-mini.mp4
 2 | cam2 | data/cr-mini.mp4
```

This means both video feeds show the exact same content. If the video is a short loop, it may look static.

## Why 502 Bad Gateway Occurs

The container was restarted (I was fixing the Dockerfile). During restart, nginx can't reach FastAPI → 502. This is normal and temporary.
